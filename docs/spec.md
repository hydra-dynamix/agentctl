# agentctl — Specification

Date: 2026-06-12
Status: approved direction; implementation tracked via LDGR (`.ldgr/ldgr.db`)
Crate name: `agentctl` (verified available on crates.io 2026-06-12)

## What this is

A light Rust library + CLI that lets expensive LLM agents (Claude, GPT, etc.)
run noisy commands and long-running agent tasks while receiving **compact,
bounded, structured reports** instead of raw output. A `cargo build` emits
hundreds of lines; the model only needs the exit code, duration, and the
handful of lines that matter. Context is the scarce resource — agentctl
protects it.

Extracted from devkit (`dev agent` / `dev summary` were added there by
mistake). The donor implementation is in `reference/` — `agent.rs`,
`summary.rs`, `exec.rs`, `output.rs` — lifted verbatim from devkit at commit
ae347b2. Port the logic; do not import devkit types (`AppState`, `DevConfig`,
dispatch helpers). The reference directory is deleted in the final block.

## Design principles

1. **Bounded by default.** Every output path has a byte ceiling. Raw output
   is always preserved on disk for forensics, never dumped to the caller.
2. **Machine-first output.** Every subcommand supports `--json` with a
   stable schema. Human-readable text is the default but JSON is not an
   afterthought — an LLM tool-call wrapper should parse, not scrape.
3. **Exit codes pass through.** `agentctl exec -- cargo test` exits with
   cargo's code so callers' error handling keeps working.
4. **Local summarization by default; LLM summarization opt-in.** The
   heuristic summarizer (notable-line extraction) costs nothing. An external
   summarizer command can be configured for richer reports.
5. **Light.** Small dependency tree (clap, serde, anyhow, toml; no tokio —
   std threads/processes suffice).

## CLI surface

```
agentctl exec [--json] [--raw] [--label <name>] -- <command...>
    Run a command, capture stdout/stderr, print a compact summary.
    Exit code mirrors the child. --raw streams untouched output instead.
    Raw capture stored under the job directory either way.

agentctl task pr-review [--requirements <absolute-path>]
            [--confidence-threshold <0-100>] [--agent <profile>]
            [--detach] [--json] [--no-fallback]
    Resolve the open PR whose head exactly matches HEAD and launch the built-in
    review policy. Blocking findings request changes; passing low-confidence
    reviews comment without approval; passing reviews at or above the threshold
    may approve and enable merge-commit auto-merge after revalidating the head.
    See docs/pr-review-task-spec.md for the complete policy.

agentctl run <agent> [--prompt <text> | --prompt-file <path>]
            [--detach] [--sandbox] [--iterations <n>] [--cwd <dir>] [--json]
    Launch a configured agent. Foreground: summarized report per iteration.
    --detach: returns a job id immediately.
    --sandbox: opt into workspace-write for a codex exec profile; Git metadata
    remains read-only. Codex defaults to danger-full-access without this flag.

agentctl status <job-id> [--tail <n>] [--json]
agentctl list [--json]
agentctl logs <job-id> [--follow]      # the one place raw output is shown
agentctl config [generate|check|show]
```

## Configuration

`~/.agentctl/config.toml`, overridable per-project by `./agentctl.toml`
(project file wins). Generated by `agentctl config generate`.

The LDGR integration additionally reads the ordered harness selection from
`~/.ldgr/config.toml`, with `~/.ldgr/config.json` retained as a legacy fallback.
Agentctl discovers commands from platform-correct `PATH`/`PATHEXT` semantics,
uses `USERPROFILE` when native Windows does not provide `HOME`, and exposes
`agentctl discover [--json]` for recovery diagnostics. Explicit agent profiles
win; only the generic LDGR profile may automatically fall through to another
LDGR-selected runnable harness.

LDGR-owned profiles negotiate `ldgr.launcher-compatibility.v1` before worker
startup. Agentctl 0.1.2 requires Core `>=0.1.13, <0.2.0` and recovery schema 1.
Failure is an infrastructure error with code `core-incompatible`; it is written
through Core when supported or atomically spooled for import after Core upgrade.

```toml
[summary]
max_output_bytes = 16384     # cap on captured output considered
tail_bytes = 4096            # tail window when bounding
max_preview_lines = 12       # notable-line preview length

# Optional external summarizer: receives bounded output on stdin,
# emits the summary on stdout.
# summarizer_command = ["claude", "-p", "Summarize this build output"]

[agents.codex]
command = ["codex", "exec", "--sandbox", "danger-full-access"]
prompt_stdin = true
# cwd = "/path/to/project"

[agents.claude]
command = ["claude", "-p"]
prompt_stdin = false         # prompt appended as final arg

[providers.openrouter]
kind = "openrouter"
base_url = "https://openrouter.ai/api/v1"
api_key_env = "OPENROUTER_API_KEY"
model = "openrouter/auto"

[agents.openrouter-api]
provider = "openrouter"      # native HTTP provider
prompt_stdin = true

[agents.openrouter]
command = ["pi", "--provider", "openrouter", "--model", "openrouter/auto", "--print", "--no-session"]
prompt_stdin = false
```

A provider can resolve its key from `api_key_env` or `api_key_command`. The key
is never stored in job records or logs. OpenRouter uses its Chat Completions
endpoint. Other provider clients remain external commands.

Job records and raw logs live under `~/.agentctl/jobs/<job-id>/`
(`job.toml`, `output.log`, `exit-code`).

## Library API (lib.rs surface)

```rust
pub struct CaptureOptions { max_output_bytes, tail_bytes, .. }
pub struct CapturedRun { exit_status, elapsed, stdout, stderr, raw_log_path }
pub fn run_captured(argv: &[String], options: &CaptureOptions) -> Result<CapturedRun>;

pub struct Summary { command, exit_code, duration, preview_lines, raw_log_path }
pub fn summarize(run: &CapturedRun, config: &SummaryConfig) -> Summary;   // local heuristic
pub fn summarize_with_command(run, config, summarizer_argv) -> Result<Summary>;

pub struct JobRecord { id, agent, state, pid, started_at, .. }
pub mod jobs { pub fn launch_detached(..), status(..), list(..) }
```

JSON schema for `--json` mirrors these structs with serde; document it in
the README and treat it as semver-relevant.

## Work blocks

### Block A1 — `scaffold-crate`
Single crate, `src/lib.rs` + `src/main.rs` (clap). Config module with
load/generate/check (toml, serde). Error handling via anyhow at the binary
boundary, thiserror or anyhow in lib (pick one, justify in a comment in
lib.rs). GitHub Actions CI: fmt, clippy -D warnings, test, build. MIT
license, .gitignore. Acceptance: `agentctl config generate && agentctl config
check` round-trips; CI workflow valid; full local verification suite passes.

### Block A2 — `summarized-exec`
Port capture + bounding + local summary from `reference/{exec,output,summary}.rs`
into the library, implement `agentctl exec` (incl. `--json`, `--raw`,
exit-code passthrough, raw log persistence) and the optional external
summarizer hook. Acceptance: `agentctl exec -- cargo --version` and a failing
command both produce correct summaries, exit codes, and raw logs; unit tests
for bounding (UTF-8 boundary clamps) and notable-line extraction.

### Block A3 — `agent-jobs`
Port the agent runner from `reference/agent.rs`: configured agents,
foreground summarized runs with iterations, detached launch with job
records, `status`/`list`/`logs`. Acceptance: detached job with a trivial
agent command (e.g. `["bash", "-c", "echo done"]`) round-trips through
run → status → logs; stale-pid detection works.

### Block A4 — `tests-docs-polish`
Integration tests (assert_cmd) covering the CLI surface incl. JSON schema
assertions. README written for the actual audience: a human wiring agentctl
into an LLM tool loop (Claude Code, codex) — include a worked example of
wrapping `cargo test` and one of a detached long task. crates.io metadata,
`cargo publish --dry-run` green. Delete `reference/`. Acceptance: all of the
above verified.

## Out of scope

- Publishing (user-triggered).
- Native provider APIs other than OpenRouter.
- MCP server mode, daemon mode, TUI — maybe later; do not scaffold for them.
- devkit integration (devkit removes its agent/summary commands separately).
